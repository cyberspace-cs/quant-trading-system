# 01 · 五层架构与逐层详细设计

> 对标九坤 / 明汯 / 幻方 的通用工业级量化交易架构。自上而下五层 +
> 配套监控归因、运维调度、**回测 / 仿真 / 实盘三环境隔离**。

---

## 1. 系统定位与核心业务需求

### 1.1 业务定位

面向 A 股 **中高频、中频多因子、日内 T+0、套利、AI 量化** 策略的全链路交易系统。

九坤核心特点：
- **数据工业化**（行情 / 基本面 / 另类数据统一入湖）
- **因子工厂**（原始 → 中性化 → 合成 → 模型打分）
- **AI 模型迭代**（PyTorch / XGBoost / LightGBM 持续训练）
- **超低延迟执行**（TWAP / VWAP / 自适应拆单）
- **多层矩阵风控**（事前 / 事中 / 事后）
- **三环境隔离**（离线回测 + 仿真 + 实盘）

### 1.2 核心功能需求

| # | 模块 | 职责 |
|---|------|------|
| 1 | 数据中台 | 行情 / 基本面 / 另类数据实时入库、清洗、对齐、因子自动生产 |
| 2 | 策略研究平台 | 因子挖掘、模型训练、回测、参数寻优、绩效分析 |
| 3 | 仿真交易 | 模拟撮合、滑点模拟、资金模拟、策略验证 |
| 4 | 实盘交易引擎 | 信号生成、拆单算法、智能执行、订单全生命周期管理 |
| 5 | 多层风控 | 事前拦截、事中实时监控、事后归因止损 |
| 6 | 资产与持仓管理 | 实时净值、仓位、盈亏、杠杆、行业暴露度统计 |
| 7 | 运维监控归因 | 延迟监控、胜率、夏普、最大回撤、因子收益拆解 |

### 1.3 非功能核心指标（私募硬标准）

- 行情延迟：微秒级 ~ 毫秒级
- 信号生成：单策略毫秒级
- 下单延迟：百微秒级
- 系统可用性：交易日 99.99%
- 风控生效：事前强拦截、零违规下单
- 数据一致性：行情、持仓、订单、资金强一致（盘后校准）
- 迭代效率：新策略从回测到实盘 1 天内上线

### 1.4 业务约束

- A 股日内不能裸做空、有涨跌停、T+1 → 必须适配合规拆单
- 单票仓位上限、行业集中度、单日最大亏损、回撤阈值强约束
- 高频场景禁止大单冲击市场 → 智能分片、时间切片拆单
- 所有策略可灰度、可熔断、可一键关停

## 2. 整体五层架构

自上而下：**研究层 → 数据层 → 策略计算层 → 风控层 → 交易执行层**
配套：**监控告警、归因系统、运维调度、三环境隔离**

```
研究层(回测/仿真) ─┐
                  ├─▶ 数据层 ─▶ 策略层 ─▶ 风控层 ─▶ 执行层 ─▶ 台账层
监控/归因/调度    ─┘
```

核心通信范式：**事件驱动 EDA + Kafka 事件总线 + Redis 低延迟缓存 + MySQL 强一致台账**

| 层 | 输入 | 输出 | 关键技术 |
|----|------|------|----------|
| 数据中台 | 原始行情 / 另类数据 | 清洗对齐后的因子、盘口 | Kafka + Flink + Redis + ClickHouse |
| 策略引擎 | Redis 因子池 + 盘口 | 标准化调仓信号 | Python 研究 + Go/C++ 实盘 |
| 风控引擎 | 调仓信号 + 实时持仓 | 放行 / 拦截指令 | Redis 预载规则 + 内存计算 |
| 交易执行 | 合规信号 | 券商柜台委托 | TWAP/VWAP + 订单状态机 + FIX |
| 资产台账 | 成交回执 | 持仓 / 资金 / 绩效 | MySQL + 盘后三账合一 |

## 3. 逐层详细设计

### 3.1 数据中台层（量化核心壁垒）

**数据来源**
- 行情：逐笔 Tick、1s K、1min K、日线、盘口深度
- 基本面：财报、营收、利润、股本、行业分类
- 另类：舆情、龙虎榜、资金流、北向、融资融券、订单流

**技术栈**
- 实时接收：C++/Go 行情订阅客户端
- 消息队列：Kafka（分区有序、高吞吐）
- 实时计算：Flink 实时清洗、对齐、复权
- 时序存储：InfluxDB / ClickHouse
- 因子缓存：Redis
- 离线数仓：Hive、Spark（批量因子挖掘、回测）

**核心能力**
1. 数据对齐：时间戳对齐、复权处理、停牌剔除、涨跌停标记
2. 因子工厂（九坤核心）
   - 量价因子：动量、反转、波动率、量比、资金流
   - 基本面因子：价值、成长、盈利、质量
   - AI 因子：深度学习残差特征、时序 Embedding
3. 因子分层：原始因子 → 中性化因子 → 合成因子 → 模型打分

> 详见 [02-redis-design.md](./02-redis-design.md) 的 Redis 专属设计，
> 与 [03-mysql-design.md](./03-mysql-design.md) 的 MySQL 静态配置设计。

### 3.2 策略引擎层（核心赚钱模块）

**支持策略类型**
- 中频多因子选股（九坤主力）
- 日内高频均值回归、动量策略
- 跨期套利、统计套利
- AI 深度学习预测模型（LSTM / Transformer）

**技术栈**
- 计算引擎：Python（研究）+ Go/C++（实盘加速）
- 模型框架：PyTorch、XGBoost、LightGBM
- 调度：K8s 弹性扩容（开盘扩容、盘后缩容）

**运行逻辑**
1. 盘中实时拉取 Redis 最新因子、行情
2. 模型批量打分、股票排序、权重分配
3. 对比当前持仓，生成调仓信号：买入 / 卖出 / 加仓 / 减仓
4. 多策略信号聚合、对冲、降噪
5. 输出标准化委托指令，下发风控层

**核心设计亮点**
- 策略热更新：不停机更新参数、模型权重
- 信号防抖：短时间抖动信号过滤，降低换手磨损
- 行业 / 市值中性化：避免风格偏移、控制回撤

### 3.3 风控引擎层（九坤矩阵式多层风控）

> 九坤风控最大特点：**事前拦截 > 事中监控 > 事后熔断，三层不可逆**

**（1）事前风控（下单前 100% 拦截）**
- 单票最大仓位 / 单行业最大暴露度
- 单日最大亏损额度 / 单策略最大回撤阈值
- 禁止涨跌停挂单、禁止 ST、禁止停牌
- 单笔委托金额、手数上限
- 杠杆率上限、集中度上限

**（2）事中实时风控（毫秒级监控）**
- 实时净值回撤监控
- 实时行业、风格、因子暴露监控
- 异常行情熔断（闪崩、暴涨暴跌）
- 换手率超限告警

**（3）事后风控 & 止损**
- 日终绩效归因
- 策略超额回撤自动关停
- 连续亏损降仓、暂停交易

**技术实现**
- 风控规则预载 Redis，毫秒级判断
- 违规订单直接丢弃、不进柜台
- Kafka 实时落风控日志，可回溯审计

### 3.4 交易执行层（超低延迟算法交易）

**解决核心痛点**：冲击成本、滑点、拆单隐蔽性、延迟抖动

**核心能力**
1. 智能拆单算法：TWAP（时间切片）/ VWAP（量加权）/ 自适应动态拆单
2. 防冲击市场：大单切碎、间隔下发、避免被对手盘捕捉
3. 订单状态机：初始化 → 已报 → 已成 → 部分成 → 撤单 → 废单，全状态闭环
4. 失败重试、补单逻辑：网络抖动自动重试、缺量补单

**技术栈**
- 柜台对接：券商 FIX 协议、原生 API
- 订单缓存：Redis Hash 存实时订单簿
- 订单持久化：MySQL 订单主表 + 分表

### 3.5 资产台账与绩效层（强一致兜底）

**MySQL 核心表（工业级）**
1. 持仓表（每日快照 + 实时增量）
2. 订单表（所有委托流水，不可修改）
3. 成交明细表（逐笔成交）
4. 资金表（可用、冻结、总资产、净值）
5. 风控日志表（所有拦截记录审计）
6. 策略绩效表（夏普、最大回撤、胜率、盈亏比）

**一致性保障**
- 交易结果以券商柜台回执为唯一真值
- Redis 做实时展示，MySQL 做落地对账、日终校准
- 每日盘后自动对账：持仓、资金、成交三账合一

## 4. 核心中间件 & 存储选型

| 组件 | 角色 | 存什么 |
|------|------|--------|
| **Redis** | 量化绝对核心 | 实时行情、盘口、因子池、实时持仓、在途订单、风控阈值、计数器、黑白名单、运行状态 |
| **MySQL / TiDB** | 强一致兜底 | 账务、审计、规则、静态配置、流水台账 |
| **Kafka** | 全系统事件总线 | 行情/信号/下单/成交回执/风控告警事件（解耦 + 回溯回放） |
| **ClickHouse / InfluxDB** | 时序存储 | 海量 Tick、分钟 K、回测数据源 |
| **K8s** | 弹性调度 | 开盘峰值扩容计算节点 |
